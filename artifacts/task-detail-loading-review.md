## 原因与本次修改

1. HTTP/1.1 下首屏静态资源占据连接：多份脚本排队 3–4 秒，任务 API 直到第 4.8–6.2 秒才开始。非首屏图、审批、报告等标签页改为按需加载；默认会话仍直接加载。
2. 字体包导入连带预加载 5 个像素字体。只定义可选 Square 字体并关闭其预加载，保留字体选择及默认字体。
3. 嵌入式静态文件没有明确的缓存寿命。为 `/_next/static/` 的构建版本化资源增加一年 immutable 缓存；HTML、路由数据及非版本化文件使用 no-cache 重新校验。仅影响 Go 嵌入式托管，外部反代仍需独立配置。
4. 详情初始化 Promise.all 等待统计完成后才挂载会话。改为任务信息到达即显示，统计返回后补充，保留请求代次保护。另一刷新样本任务 5590 ms 返回，统计 5959 ms 返回，形成约 369 ms 的额外等待。
5. 意图资产单次约 425 KB / 6.1–6.4 秒，5 秒定时器在前次未结束时继续发请求。资产与意图列表增加在途保护，避免重叠及旧结果乱序写入。没有延长封禁或 Worker 取消的后端执行窗口。

## 尚待验证 / 下一优先级

- 新代码未部署，因此没有优化后生产 LCP 数字；必须同环境部署后复测，不把构建体积降幅当成加载时间降幅。
- 生产建议在域名 HTTPS 入口启用 HTTP/2、静态压缩，并检查反向代理是否保留缓存头。当前不改生产配置。
- 首屏重复查询拦截数据、返回链接预取以及约 492 KB logo 仍有优化空间；优先于无依据删除业务代码。
- SSE 是长连接，Network 面板中的连接持续时间不等于首次加载耗时；本记录单独区分文档、静态资源、历史和资产接口。

## 第二轮阻塞链修复

- `intent-assets` 改为与会话列表相同的 300 条意图分页；加载更早会话时同步加载对应资产，旧无参数调用仍保留兼容行为。
- 授权检查从“每个意图/资产结果行调用”改成“每个不同资产计算一次当前任务有效状态、每个来源任务/资产组合计算一次来源状态”。来源只读、父资产继承、封禁、撤回和墓碑语义不变。
- 浏览器离开详情页会取消资产映射请求，Go 请求上下文和 20 秒上限继续传入 PostgreSQL；取消不再占用连接池，服务端超时返回 504。
- 任务详情改用 `/api/stats?task=...&compact=1`，不再串行统计全局流量、全局资产和未使用的节点分类；省略 `compact` 的兼容接口和无 task 参数的仪表盘响应继续返回全局统计。
- 单任务详情的归档依赖从全表分组查询改为按当前任务索引查询。
- 任务详情和统计轮询使用独立在途状态，慢统计不再阻塞任务信息刷新；父组件统一获取待处理拦截记录，会话组件不再重复请求。
