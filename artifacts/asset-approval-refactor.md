# 资产审批重构交付说明

## 行为

- 保留三个任务模板：全部自动批准、关联资产自动批准、仅用户提供资产自动批准。
- 审批粒度统一为域名/IP；端口、服务、接口不独立审批。服务和接口继承主机权限。
- 用户主动封禁、撤回、删除域名/IP仍优先于自动批准。删除服务/接口只隐藏记录，不撤销主机权限。
- Agent 资产及副作用父主机通过同一事务登记。待审批发现只向模型返回数量，不返回候选资产列表，也不计为可执行资产写入。
- 调用模型前重新过滤已持久化的结构化资产和图节点工具结果；不修改审计原文。没有可执行目标、只剩待审批目标时，框架暂停规划。
- 命令目标提取不再通过域名子串正则匹配本地文件名，覆盖 Windows curl 输出文件示例。
- 页面和 Mock 同步模板说明及服务/接口删除语义。

## 重要边界

- 不保证原始网页、命令输出或模型自行生成的文字完全不含未审批主机；过滤针对框架结构化资产/图结果及调度入口。执行层继续保留授权检查。
- Shell 提取是静态解析，不执行变量或脚本来求值；不是完整 Shell 解释器，HTTP 出口检查仍是必要防线。
- 用户提供资产不会授权其他无关任务。
- 未修改生产数据库，未重排历史任务编号，未自动提交或推送。

## 任务编号核查

`tasks` 使用独立的 `tasks_id_seq`；`task_asset_grants` 没有自增编号。独立 PostgreSQL 测试验证插入 100 条授权记录不会推进任务序列。生产环境中任务 7 到 49 的具体来源尚未确认；序列间隔本身不能证明表混用，不应为追求连续编号重置序列。

## 验证范围

- 独立 PostgreSQL 16 测试库：三模板、DNS 关联、主机封禁恢复、服务/接口删除、任务序列、结构化上下文过滤及完整数据库回归。
- Agent、服务端及 Guard 回归；命令解析和待审批上下文的定向 race 检查。
- 前端 TypeScript、生产构建、审批 Mock 测试、定向 Biome 和差异检查。
- 最终测试结果以交付回复为准。

重复运行发现旧重试配置测试先关闭连接、后执行清理，造成重名残留；已调整清理顺序，并通过连续两轮定向验证。一次全包回归中的两项服务端测试出现临时目录清理竞争（`TestCoreTaskLifecyclePG`、`TestInheritedActivityDetailAndRelationDeletion`）；单独服务端回归通过，整套重复运行稳定性仍需关注。

最终全包复测：数据库通过（150.920 秒），Agent、Guard 及其他包通过；服务端 `TestResolveChatAgentHonoursConversationProfile`、`TestInheritedActivityDetailAndRelationDeletion` 因 `TempDir RemoveAll cleanup: directory not empty` 失败。尚未修复服务端测试后台任务退出与临时目录清理竞争，不宣称全包全绿。定向 race、TypeScript、前端构建、Mock、Biome、`git diff --check` 均通过。
