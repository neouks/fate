# 页面性能修复核验（2026-09-19）

基线：9386e9e。修复审批轮询、播报板响应大小与请求取消、搜索查询成本。本次未修改业务数据库或部署应用。

## 改动

1. 审批页采用串行轮询，上一轮结束后再等待 5 秒发起下一轮；历史和待审批响应分别更新。刷新、切换筛选、离开/隐藏页面取消旧请求；浏览器请求设 15 秒期限。任务审批页只查询该任务的待审批记录。历史与待审批 SQL 接收取消上下文，并设 10 秒期限。
2. 播报板列表只返回最多 200 条摘要，每条摘要最多 500 字符；不自动加载关联边或邻居正文。展开后通过新增 `/api/exploration/nodes/{id}` 读取每页最多 50 条关联及 16,000 字符正文，可继续分页读取全文。详情与列表均按任务隔离。
3. 播报板采用串行轮询，隐藏页面暂停、卸载取消，历史页后台仅查计数。初次加载失败可见并可重试；详情分页失败重试原分页位置。
4. 节点数字 / #数字查询改为纯 ID 精确匹配，不再同时扫描正文。@ 引用查询将精确 ID 和模糊搜索分支拆开；仍保留精确匹配优先、模糊结果以及游标分页。匹配表达式采用 trigram 索引，取消/超时贯通查询。

## 数据库上线说明

沿用启动迁移入口，新增 pg_trgm 扩展、4 个文本搜索 GIN 索引和 exploration_id/id 复合索引。使用 CREATE INDEX CONCURRENTLY，并检查/重建中断后遗留的无效索引。首次升级需要等待索引创建，会增加启动时间、存储和索引维护开销；并发创建允许其他应用实例继续读写。数据库需允许创建 pg_trgm 扩展。未在业务库执行此次迁移。

极短或高频关键词可能仍匹配大量记录，深分页和精确总数也仍有成本；本次不宣称所有数据规模下延迟恒定，相关请求已有取消与超时保护。
