# 内置工具与调用契约审查

## 范围

检查代码中的 27 个领域工具、21 个编排/平台工具、3 个流量工具，以及 SDK 普通调用、延迟调用、默认值、权限/Hook 改参、数据库覆盖路径。7 个跨任务包装工具已加入底层契约一致性测试。未检查生产数据库中的自定义内容，也没有对外部 MCP 服务进行实际调用。

## 确认问题与修复

| 问题 | 修复 |
| --- | --- |
| 跨任务工具手写旧 Schema，丢失轨迹分页、节点分段字段；说明仍声称返回完整结果 | 从任务内同一实现派生 Schema/说明，仅增加 task_id，并改写跨任务工具引用 |
| SDK 只读取 []any 格式的 required，代码中的 []string 被忽略 | 同时支持内存和 JSON 往返后的形式，增加等价测试 |
| Schema 的 minimum/maximum、enum、minItems/maxItems 未执行 | 补齐校验；additionalProperties=false 时拒绝未知字段，未声明时不改变已有开放对象语义 |
| 权限处理或 Hook 改参后不复验 | 执行前校验每次更新后的参数，异常不调用工具 |
| 默认值在权限和 Hook 后才注入；普通/延迟调用不同步 | 提取共享默认值实现，统一在校验和 Hook 前展开；删除应用层重复实现，防止 null 输入引发 map 写入 panic |
| 平台、自定义、流量工具忽略 JSON 解码失败 | 解码失败明确返回，不继续使用部分解析数据 |
| 漏洞证据 API 返回数字 ID，工具却声明字符串 ID | finding_id/binding_id 统一声明正整数；task_id 保留平台既有字符串契约 |
| 旧数据库参数和说明覆盖新协议 | 内置结构以代码为准，合并兼容字段说明及默认值；分页/写回协议使用代码说明，数据库原文不改写 |
| 工具禁用后提示仍要求执行 | 核心工具启动检查；可选工具以本轮可用集合为准；流量绑定关闭时明确覆盖旧绑定指令 |
| 批量事实与单条字段重复定义 | 共用字段定义，批量嵌套类型和 required 同步 |
| 错误名称只有 unknown tool、分页报错笼统 | 有限的当前可用名称候选、具体分页范围及 DSL 纠错；无别名，无自动执行 |
| 超时切换收尾上下文与旧工具线程存在竞态 | 每轮执行器保存上下文快照，旧调用不继承收尾阶段的新上下文 |

## 验证方式与边界

- 自动化目录测试核对名称、必填字段和重复注册；包装工具 Schema 去掉 task_id 后必须与底层一致。
- SDK 测试覆盖 required/枚举/边界的内存与 JSON 一致性、默认参数在 Hook 前可见、非法 Hook 改参不执行、错误名称不触发写入、超时上下文隔离。
- Agent、Server、Traffic 数据库测试使用独立 PostgreSQL 临时容器，不使用业务数据库；数据库按测试包隔离。
- 执行 SDK race、全包编译和 git diff --check。
- 没有将 page、offset、before 强行统一：三者对应不同接口契约，包装层应复用而非另造协议。
- 本次没有增加别名或自动纠错执行；模型仍可能第一次拼错名称。校验器仍是受支持关键字的轻量实现，不宣称完整支持所有 JSON Schema/MCP 方言。
- 本记录包含此前未提交的相关修复；不自动提交或推送，不修改历史会话。
