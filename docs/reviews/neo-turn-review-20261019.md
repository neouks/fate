# Neo 风格对话组成与执行详情复审

2026 年 10 月 19 日。本次增量改造已发布到 `http://localhost:5173`，后端版本为 `neo-turn-ui-20261019`。工作树基于 `dc2d7d9b`，保留此前未提交修改和配置。

每轮执行现在按“状态与耗时 → 可折叠过程 → 最终答复 → 时间与复制”展示。最终答复来自宿主确认的原生响应或验收结果引用；不会按最后一段文字猜测完成。历史记录没有可靠边界或统计时保留原顺序，详情显示“未记录”。

## 修复范围

| 项目 | 实现及复审结果 |
| --- | --- |
| 执行身份 | 原有 `turn_id`、`stream_id` 保留。新增运行元数据及原生响应完成元数据，纯工具响应也能统计步骤。 |
| 过程与答复 | 共享 Transcript 使用 Message、Bubble、Collapsible。中间正文、思考与工具按顺序展示；最终答复独立保留。“回复完成”和空 usage 不生成独立气泡。 |
| 折叠行为 | 正在执行默认展开，用户折叠后保持；结束自动收起，用户主动展开的记录保持。没有过程内容时不显示空折叠组。 |
| 工具与错误 | 沿用调用 ID 配对、原始参数和结果续读。收起时保留失败数量、执行错误和审批入口。纯工具执行无正文时禁用空复制。 |
| 流式与恢复 | 沿用已有 SSE、短批快照、增量合并及 MessageScroller。摘要先于最终活动到达时也会移除对应临时文字，不留下重复正文。 |
| 搜索与分页 | 定位折叠内容时展开对应过程及原工具详情；统计来自完整持久记录，不依赖当前页面的活动数量。 |
| 状态 | 区分失败、预算耗尽、停止及等待宿主确认。执行器退出先等待确认；缺失确认超过 12 秒时仅将展示状态标为中断，不改写业务终态。 |
| 运行统计 | 恢复后的同一 turn 汇总多个 runtime 的请求审计，只使用最新 runtime 判断活跃状态。角色、主会话段／独立会话、意图关联按实际记录展示。 |

主要实现：`apps/server/src/engine/turn-summary.ts`、`engine/live-stream.ts`、`engine/runtime-config.ts`、`pi/runner.ts`、`http/activity-stream.ts`、`http/routes/turns.ts`，以及 `web/src/components/transcript.tsx`、`hooks/use-turn-summaries.ts`、`lib/turn-summary.ts`。任务、独立会话和复测写入链路均接入相同元数据。

未修改 pi 模型循环、Agent 工具权限或双图调度规则。Worker 恢复回归中的启动夹具改用正式准入入口，以符合工作区现有的任务准入约束。

## 接口与统计口径

- `GET /api/tasks/:id/turns?ids=turn1,turn2`
- `GET /api/conversations/:id/turns?ids=turn1,turn2`
- 已有 SSE 新增 `event: turn_summary`，数据为 `{ items, requested_ids }`。旧客户端可忽略；打开详情不创建新订阅。

批量接口最多接受 100 个去重后的标识，返回 `{ items: TurnSummary[] }`。摘要包含版本、执行标识、状态、开始／结束时间、等待时间、模式、角色、关联、模型序列、步骤、工具调用和失败次数、usage，以及 `final_activity` 引用。原始正文仍通过原活动详情接口读取。

摘要是展示投影，不是第二套调度状态。其来源为持久活动元数据、runtime 与请求审计；新增活动 turn 索引，不重写历史记录。任务接口沿用探索图授权投影；独立会话沿用所属任务及复测漏洞的授权检查。未授权、跨任务及撤销父资产授权的回归均通过。

| 字段 | 口径 |
| --- | --- |
| 开始与耗时 | 进入宿主 prompt 的实际开始时间，到宿主终态；排队／请求等待单列。 |
| 步骤 | 每个原生 assistant 响应按 stream ID 去重。思考、文字、同一响应中的并行工具只计一步。 |
| 工具调用 | 按调用 ID 去重，包含失败调用；失败数单列。 |
| 模型 | 优先使用请求审计中的实际模型序列，不显示内部路由模型代替实际供应商。 |
| Token | 汇总输入、输出、缓存读取及写入。压缩、失败／中断请求的已知用量包含在总数中，并分项显示。供应商未返回用量时标注部分未知。 |
| 最终答复 | 宿主成功确认后的明确最终响应，或宿主提交的验收／部分结果。失败或中断的普通模型文字不会提升为成功答复。 |

## 验证结果

全部验证使用本地合成资料或确定性模型，本轮付费模型请求和外部测试目标请求均为 **0**。

| 检查 | 结果 |
| --- | --- |
| 服务端完整回归 | 39 个文件，437 通过、1 跳过，277.33 秒。跳过项为真实 DeepSeek 模型列表请求，不计通过。 |
| 前端数据契约回归 | 36 通过、0 失败、0 跳过。 |
| 类型与构建 | 前后端类型检查、服务端构建、Next 普通构建及静态构建通过。 |
| 流式可见更新 | 最后一次 4 个样本：收到事件后 4、5、5、2 ms 更新正文，均早于消息完成。夹具写入到 DOM 为 58–164 ms。 |
| 生成中刷新 | 最后一次 405 ms 恢复已持久内容及有效快照。 |
| 重复与错误 | 最终答复只显示一次；测试页面无未捕获浏览器错误。 |
| 响应式 | 390、846、1280、1440px 的明暗主题，无页面水平溢出；390px 详情浮层保持在屏幕范围内。 |
| 键盘与展开 | 详情 Escape 关闭后焦点返回；手动折叠、原工具参数／结果及最终答复可见性通过。 |

专项覆盖纯工具模型响应、并行／重复调用、失败和预算终态、历史缺失值、压缩及候补模型用量、跨 runtime 恢复、过期执行器、摘要与最终记录到达次序、鉴权及资产授权撤销。完整回归另覆盖既有双图、黑板、恢复、强杀和权限链路。

八类角色均使用共享执行组件。Main 在中央对话验收；Goals、Planner 和 Worker 在右侧过程验收；Auto、Pentest、Reporter、Retester 在独立会话验收。Worker 的验收结果保留在折叠过程之外。这里的八类浏览器入口使用合成活动；原生 pi 接线使用服务端 faux 模型回归，未把合成展示测试宣称为真实供应商执行。

一次并发完整回归期间的刷新测量超过 2 秒，单独复测为 405 ms；两次测量不能作为所有机器负载下的延迟保证。验收脚本也修正了重复运行时旧夹具计时文件、离屏内容和重名会话的选择问题。
