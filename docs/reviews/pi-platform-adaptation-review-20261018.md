# pi 原生平台适配验收与复审

本轮在现有未提交修改上增量适配非编码场景，保留 pi 1.3.0 的会话、模型与工具循环、压缩边界及持久化。默认采用领域压缩与 MCP 延迟发现；用户自定义提示词、现有工具绑定、双图、审批、冷图和来源任务继承继续生效。SDK 源码和依赖版本未修改。

## 实施结果

| 批次 | 最终行为 | 主要位置 |
| --- | --- | --- |
| 运行配置 | 八类角色必须显式提供提示词、工具集合；检查执行能力和工作目录；配置带版本并在下一会话生效 | `src/pi/platform-policy.ts`、`src/engine/runtime-config.ts` |
| 领域压缩 | 原生 `session_before_compact` 保留 SDK 切分边界及近期消息；宿主保存授权投影、意图与证据引用，模型补充历史工作摘要 | `src/pi/domain-compaction.ts`、`src/agent/domain-state.ts` |
| 工具发现 | 原生 MCP 与 `tool_search` 完成连接、检索、加载和调用；内部写回工具保持直接装配 | `src/pi/platform-mcp.ts`、`src/agent/resources.ts` |
| 可观测性 | 记录有效策略、当前工具、分项大小和摘要请求用途；摘要 usage 计入总量 | `src/pi/modelResolver.ts`、`src/http/routes/agents-config.ts` |

领域摘要区分事实、推测和线索；不根据摘要自动提交事实、完成意图或授予权限。Worker 检查点引用当前执行约定，并保存当前节点版本、进度、结果及相关事实的可展开索引。Reporter 保存待生成报告标识，Retester 保存固定快照的读取入口和已提交结论。事实和证据正文仍由已有授权工具查询。

压缩失败、空输出、截断、取消或预算不足时，取消本次压缩并保留原始记录，不静默使用默认摘要。回退模式调用 SDK 自带的摘要生成函数，保留其格式与文件追踪，同时逐次执行宿主限流、候补、审计和预算检查。

## 复审发现与关闭

| 问题 | 修复与验证 |
| --- | --- |
| 摘要调用绕过对话 `message_end`，导致审计和 usage 遗漏 | 独立记录 `purpose=compaction`，每次物理摘要请求只结算一次；失败切换和原生分段摘要均有数据库回归 |
| SDK 已为对话选定模型，又在发送前压缩，单个审计槽被摘要覆盖 | 对话与摘要分别保存待结算请求及实际模型索引；会话退出时关闭未完成记录；专门重现交错顺序 |
| 摘要耗尽额度后继续发送下一次对话请求 | 原生 `turn_start` 再检查对话与摘要共享预算；测试确认不会发出额外模型请求 |
| 请求级较小输出限制被模型配置覆盖 | 按请求限制和配置限制的较小值发送；三种模型协议均检查实际 HTTP 请求 |
| 扩展异常被 SDK 捕获后可能回退默认压缩 | 压缩扩展明确返回取消并终止当前运行，宿主返回可恢复错误；手动与自动压缩均验证 |
| 已发现的 MCP 工具在权限撤销后仍可能被选择 | 搜索按实时绑定过滤，移除撤销工具的当前声明；调用再次校验；恢复后不恢复授权 |
| 资源型 MCP 的就绪状态与原生资源工具被遗漏 | 初始化无 tools 能力时直接就绪；按角色装配资源列表与读取工具，保留禁用配置；资源型服务专项回归 |
| MCP 连接失败被误解为空搜索结果 | 返回服务不可用错误；本地故障服务验证未产生目标工具调用 |
| Auto 未绑定任务时丢失已绑定的平台 MCP 集成 | 按 Auto 角色绑定装配；仍禁止本地 Bash、Write、Edit 能力 |

本轮最终检查覆盖角色装配、压缩与恢复、工具发现、模型计量和配置生效链路。调度回归沿用两个意图完成、恰好 6 次模型调用的断言，将原有 5 秒等待界限对齐到计划约定的 15 秒窗口；独立复跑耗时约 2.4 秒。最终验证结果见本目录证据中的 `verification.json`。本轮审查发现的问题均已关闭，未发现本轮改动中仍未关闭的 P1、P2。

## 成本与真实模型证据

固定本地 MCP 夹具提供 60 个允许工具及一个隐藏工具。直接加载时，首轮序列化消息为 **27,618 字节**；延迟发现时首轮为 **1,222 字节**，搜索后的下一轮为 **2,844 字节**。首轮减少约 **95.6%**，但增加了一次发现调用。这是确定性夹具的消息字节数，不是供应商实际 token 或生产费用对照。

本轮 DeepSeek 实测仅执行本地合成任务：一次 `context_search`、一句状态答复、一次领域压缩，随后重开会话读取检查点。共 **3 次物理请求**，约 6 秒；目标访问为零。与上一轮 61 次合计 **64 次**，达到授权上限。

| 请求用途 | 未缓存输入 token | 缓存读取 token | 输出 token | 请求体字节 |
| --- | ---: | ---: | ---: | ---: |
| 本地图查询 | 1,999 | 0 | 108 | 7,963 |
| 查询结果答复 | 233 | 1,920 | 39 | 8,600 |
| 领域压缩 | 1,634 | 0 | 632 | 7,597 |
| 合计 | 3,866 | 1,920 | 779 | 24,160 |

供应商报告总消耗 **6,565 token**，摘要成本已计入。重开会话没有追加模型请求。真实探针之后发现的交错审计和末次预算边界由确定性测试覆盖；预算已满，未再次调用真实模型。本轮没有进行八类角色的新旧真实模型配对，不据此声称所有角色的实际费用下降。

真实记录位于 `evidence/pi-platform-adaptation-20261018/deepseek-platform-probe.json`。隔离数据库保留供复核，测试结束后其中模型密钥已清空；凭据未写入脚本、源码、夹具或报告。

## 配置与回退

`GET /api/settings` 返回 `pi_context_policy` 和 `pi_mcp_loading`；`PUT /api/settings` 接受如下配置，并返回 `applies=next_session`：

```json
{"pi_context_policy":"domain","pi_mcp_loading":"deferred"}
```

恢复原生摘要格式及直接装配：

```json
{"pi_context_policy":"native","pi_mcp_loading":"direct"}
```

显式禁用或解除角色绑定的 `tool_search` 会使该角色使用直接装配兼容模式；被禁用的 MCP 工具仍保持隐藏。角色预览返回策略版本及未装配 Schema 的说明，不启动模型或 MCP。任务和会话的运行配置接口显示有效策略、实际工具及待生效配置。

数据库只增加 `llm_request_attempts.purpose`，历史记录默认为 `conversation`，不改写任务、审批、双图或会话。新代码在服务更新后加载；已有管理服务未重启，未修改线上 B 的配置或任务。
