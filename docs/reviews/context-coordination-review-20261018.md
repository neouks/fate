# fate 上下文协作修复与验收

本轮落实 context-coordination-plan-20261018.md 的四项实现阶段：执行约定和完成验收、去重和续跑、分层上下文、增量规划。领域状态仍由 fate 双图、锚点及数据库管理；pi 原生处理模型与工具循环、会话持久化和压缩。

## 行为变化

- Planner 工具派单必须提供 objective、acceptance 和稳定 work 身份。依据引用包含节点版本，提交与执行边界均检查其有效性。人工旧 summary 入口保留兼容约定。
- Worker 有阶段进度和逐项结果协议。宿主检查当前负责人、事实归属、证据正文、内容版本及授权；没有结果不得标记意图 done。负面验证可以完成，部分结果与阻塞分别保留恢复位置。
- 完成记录先持久化，再由宿主原子提交意图终态、结果活动和既有反馈。模型在提交后失败不抹去有效结果；重启恢复已提交结果不重放目标工具。
- 工作身份对活动及终态去重，兼顾 URL 路径、SPA hash 路由和大小写敏感身份。重试需要关联原工作并提供新依据或可恢复故障原因。暂停恢复继续原意图。
- context_search 查询摘要、事实详情和漏洞报告；context_get 按稳定节点引用分页读取原文及关系。冷图不丢原始可查节点；一层来源任务只读，不写跨任务探索边。
- 查询工具装配到任务绑定的角色，延续统一授权投影与配置开关。Main、Planner、Goals 不因此获得外部执行工具，Retester 的网络范围保持独立限制。
- 首轮只注入相关摘要，Worker 持有当前执行约定和上游引用；Planner 获得进展、结果及决策摘要。执行约定上限 12 KiB，增量事件投影上限 12 KiB，其他初始图摘要使用现有 20 KiB 有界 JSON 机制；详情按需续读。
- 领域事件由数据库事务持久化。事件逐条确认，避免较小 ID 晚提交造成遗漏；超出提示容量的可见事件保留待处理。没有领域变化时 Planner 不因心跳重复调用模型。合法等待状态包括 waiting_dependency、needs_input、exhausted。

## 复审发现与处理

1. 旧节点查询的 COALESCE 列缺少别名，负责人和来源读取错误；补齐列名，增加负责人校验回归。
2. 仅凭最终文字或资产登记可能标记完成；改为结构化结果与宿主验收。
3. 已提交结果之后模型出错可能错误标记失败；宿主优先验收已提交结果。
4. 事件只按最大 ID 或一次性确认整批，会遗漏晚提交事务或提示容量之外的内容；改为确认本轮实际交付的事件 ID。
5. 漏洞报告正文位于 findings，单读探索节点不能获得完整报告；统一详情读取，并让报告变化推进节点版本和领域事件。
6. 恢复 blocked 意图若保留当前 execution_result，会立即再次结算旧阻塞；恢复时移至 previous_result，保留检查点和原始过程。
7. 简单 URL hash 删除和身份小写化可能错误合并不同 SPA 页面及账号；保留这些身份差异。
8. Planner 默认目标占位符使用 {{Goal}}，旧渲染器仅识别 {{.Goal}}；统一支持两种写法，替换值按字面处理，保留用户目标中的美元符号序列。

## 验证方式

自动化使用隔离数据库与 faux 确定性模型。专项覆盖结构化派单、并发去重、重试前置条件、负责人隔离、证据归属、幂等提交、恢复、跨任务只读继承、长正文续读、查询游标、晚提交事件、容量外事件保留、Planner 等待、HTTP 投影，以及 pi 原生压缩后的按引用取回。

真实模型使用用户提供的 deepseek-flash 运行本地合成夹具。Worker 读取夹具、写事实、保存进度并提交结果；Planner 在缺少授权对象时记录 needs_input，禁止凑单。夹具不代表目标漏洞，测试未访问被测目标。凭据从运行时配置读取，不写入源码或此报告，隔离测试库中的临时密钥在结束后清除。

## 适用边界

- 结构化键相同的工作可确定性去重；模型为同一语义选择不同 question_key 时，仍需要检索与规划纪律，未实现语义向量去重。
- allowed_tools、资源授权及写回归属可由宿主检查。任意 Bash 命令是否在语义上推进某一意图，不能仅靠提示词严格证明。
- 本轮完成代码和隔离验收，没有重新开展远端 A/B 目标对照，没有切换正在运行的管理平台服务。
- 未进行大规模图数据性能压测；上下文上限按字节约束，模型自身的窗口压缩继续由 pi 管理。
- 所有修改保留在当前工作区，未覆盖此前未提交修改，也未创建提交。
