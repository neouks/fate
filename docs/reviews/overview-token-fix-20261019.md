# 任务详情与 Token 统计修复复审

2026 年 10 月 19 日。已发布至本地前端 `5173`、后端 `8787`，后端版本 `overview-token-fix-20261019`。本次保留已有未提交修改、历史数据及用户配置；未修改模型循环、权限或任务调度。

## 问题与修复

任务详情原来的按模型统计从 `activity.kind=result` 汇总，每条记录代表一次宿主执行，不等于一次模型请求。它还使用当前默认模型标记历史用量，遗漏未生成最终结果的请求。pi 1.3.0 的 `usage.input` 是未缓存输入，缓存读取、写入分别计量；前端直接用缓存读取除以该值，导致命中率超过 100%。

现在从 `llm_request_attempts` 按实际记录的模型汇总，包含压缩、重试／候补、失败及进行中的请求。输入总量为未缓存输入＋缓存读取＋缓存写入，缓存命中率为缓存读取÷输入总量。未知用量明确提示，不当作准确的零消耗。仅有旧执行结果的任务保留原始用量，模型、请求次数和缓存口径显示未知，不用当前配置补猜。

任务详情从右侧抽屉移入“任务”入口的二级导航：**对话、任务详情、播报**。顶部五个分类保持不变。旧 `panel=overview`、`panel=broadcast` 和旧 `tab` 链接兼容映射；切换时保留定位参数、对话订阅、草稿、未保存表单与已访问内容。过程面板仅在对话可见时显示，避免窄屏下隐藏对话的抽屉遮住任务详情。

## 实现与接口

- `apps/server/src/http/model-token-usage.ts`：请求级汇总与历史回退。
- `apps/server/src/http/routes/compat.ts`：`GET /api/llm/records/by-model?task=...` 接入汇总，校验任务参数及任务存在状态；沿用鉴权。
- `web/src/lib/model-token-stats.ts`：统一总数与缓存口径，未知或无效比例显示“—”。
- `web/src/lib/task-navigation.ts`、任务 `page.tsx`：二级页面及旧链接映射，保持会话组件挂载。
- `web/src/app/(main)/function/tasks/detail/_tabs/overview-tab.tsx`：实际请求数、输入组成、失败／压缩／进行中与未知用量，加载失败可重试。

接口继续返回 `{ models: [...] }`，保留已有用量字段，新增 `source`、`input_semantics`、`uncached_input_tokens` 及请求分类计数。审计数据的 `input_tokens` 现在明确表示含缓存的输入总量；历史回退的 `calls` 为 `null`。本次修复的是任务详情按模型统计接口，其他仪表盘／历史汇总接口未一并迁移，不能据此声称全站所有用量接口已统一。

已有请求审计的任务不叠加执行结果汇总，以免重复计量。如果历史审计只覆盖任务的一部分，显示可追溯的已记录请求；无法可靠重建的历史请求不补猜。供应商没有返回的 usage 也无法补算。
