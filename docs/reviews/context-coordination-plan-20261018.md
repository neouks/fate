# fate 上下文与意图协作实施计划

目标是让 Planner 根据可追溯的事实和执行进展派单，Worker 在一个意图内自主选择方法、及时提交证据和结果。双图、锚点、审批、冷图和来源任务继承继续作为领域基础；pi 负责原生模型与工具循环、会话恢复和压缩。

## 实施顺序

| 阶段 | 修改与验收 | 状态 |
| --- | --- | --- |
| 1 意图执行约定与结果验收 | Planner 必须提交结构化 contract/work；checkpoint_intent 保存进度，complete_intent 按完成条件引用证据，宿主重新验收版本与权限后提交终态 | 已实现 |
| 2 去重与续跑 | 活动和终态均保留工作身份；新证据或可恢复故障显式重试；保留人工 summary 入口、原意图续跑和已提交结果恢复 | 已实现 |

## 实施约束

- 保留当前未提交修改，增量迁移，不覆盖用户自定义提示词及工具开关。
- 现有 summary、parent_id、asset_ids 接口兼容；旧意图在执行时使用兼容约定，不能伪造完成结论。
- 新的结构化意图要求明确验收项。成功回答问题可以是负面结果；缺失证据、受阻或预算耗尽不等于成功。
- Worker 只能写自己的进度和结果。完成提交不直接释放租约，由宿主原子提交终态及反馈。再次消费不得重复完成。
- 事实的简报和详情引用同一节点及证据，不建立另一份独立事实库。压缩摘要不能替代原始记录。
- 工作身份按结构化字段准确查重；语义相近但身份不同的工作不自动合并，不承诺识别所有自然语言改写。
- 领域工具边界和资源授权由宿主检查；任意 Bash 的语义目的无法仅凭提示词严格证明，本轮不宣称解决这一限制。
- 在隔离测试数据库使用确定性模型夹具验证。真实模型或远端对照只有实际运行后才记为通过。

## 验收记录

实施代码覆盖四个阶段。最终检查记录见同目录的 context-coordination-review-20261018.md；真实模型与源文件指纹保存在 evidence/context-coordination-20261018/。

新接口包括 checkpoint_intent、complete_intent、record_plan_decision、context_search、context_get，以及 GET /api/exploration/:expID/context。新查询工具只在相应角色绑定的任务范围内读取，既有工具开关继续生效。Planner 使用强约定，人工旧入口使用兼容约定；用户自定义提示词保留，运行时追加宿主协议。

共享上下文事件以独立已确认标记消费，不依赖 max(id)。来源任务变更和授权变更产生持久事件；没有变化时轮询不会触发模型。节点、报告正文、进度与详细结果仍由数据库保存，模型首轮只获得可展开摘要。
