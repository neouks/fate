# 受阻后的证据范围与线索接续

参考本地 Series 源码快照 `70266a3588f3085d10c75695adef2b346d21fcbe` 中 `agent/planner.go` 与 `agent/worker.go` 的提示词。采用目标未完成时寻找不同机制、Worker 在当前意图内尝试合理替代方法、把范围外线索交回 Planner 的原则。

## 实现

- Planner、Worker、Main 共用目标与失败归因规则。结果型目标需要实际结果证据，方法失败、意图结束和执行中断不能替代达成。精确替换旧内置“否定方向最多复核一次”片段。
- Worker 先复用充分共享证据。区分技术方法受限、环境故障、前置缺失和用户/平台权限约束。独立的正向能力与负面方法结论可以批量分项保存，相关观察仍合并。
- `record_fact` 增加可选 `follow_up`，包含有证据的 `positive`、一个未解 `question` 和 `blocker` 分类。旧调用继续有效，不自动改写历史事实。
- Planner 增量交付保留线索结构，每次请求通过现有边界上下文获取最多八项重要线索摘要，包含总数、更多标志和可直接调用的字段读取坐标。正向观察不随最近完成意图窗口消失。完整内容仍保存在事实中。
- `todo_write` 增加可选 `review`，记录继续、暂缓、关闭及证据版本、适用范围和理由。暂缓要求恢复条件，关闭要求存在 evidence/scope 并有当前版本的完整读取回执。任务待办与审计活动在同一事务保存，缓存仅在提交成功后更新。
- 关闭某种方法仍保留正向事实，方向复核仅适用于其 scope。证据版本变化后旧复核不再作为当前复核显示。宿主核验的是引用和读取记录，语义结论仍属于模型判断。整表待办更新沿用未修改的既有复核，避免每轮重读旧证据。
- 精确升级此前内置 Planner、Worker、Main 默认文本，追加提示词历史，保留自定义选择和主动回退。实际模型请求中共用规则仅注入一次。

复用事实 JSON、跨轮待办和活动流，不增加执行工具或目标操作。工具配置、单问题意图、既有去重、人工暂停、停止与超时继续适用。

## 真实模型验证

使用现有配置的 `deepseek-flash`。生产数据库连接强制只读，仅获取模型配置。执行工具只读取固定离线样本，图写入位于新建的 `test_` 数据库，退出时删除。Planner 实际调用领域工具派单，但不启动派出的 Worker 或生产调度器。

| 场景 | 最终行为 |
| --- | --- |
| 共享证据已充分 | 一次模型请求，零读取、零新增事实，直接引用结果 |
| 合理读取方法耗尽 | 两种模式各试一次，保存范围与限制后结束 |
| 用户禁止替代模式 | 只尝试允许的模式，保存限制后结束 |
| 预览失败但归档仍有正向证据 | Worker 保存 follow_up；真实 Planner 读取 evidence/scope、查重、派一条归档条目读取意图；目标保持 open |
| 目标入口返回技术错误 | 在既有只读授权内切换到允许的原文模式并取得结果 |

最终五场景共21次实际模型请求，包括关键场景的两个角色。请求记录检查了共享规则单份及工具 Schema 名称无重复，最终无非预期工具错误。Planner 派单内容人工核对为同一独立验收问题。

首轮发现线索索引没有给出 field，导致 context_get 的 READ_SELECTION_REQUIRED；已改为提供字段级 read_options。另一轮发现 Worker 对充分证据做了重复确认；将先检查共享证据满足验收明确放在决策首位后通过。这些合成场景验证行为与接口，不代表任意真实任务都能达成目标，也没有重新测试任务4901的目标。
