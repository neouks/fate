# 探索图唯一协同：实施与复审记录

日期：2026-10-19（Asia/Shanghai）。运行策略：`blackboard-v1`。当前服务已加载 `blackboard-v1-20261019`，后端 `127.0.0.1:8787`，代理 `127.0.0.1:8788`。

本轮实现了“按空位规划 → Worker 执行一条意图 → 集中发布 → 会话退出释放名额 → 按新图谱补位”。隔离环境的确定性模型完整链路、强杀恢复及浏览器验收通过。真实 DeepSeek 完成了第一条意图及第二轮补位，但 11 次请求额度不足以覆盖最终自然收尾；这项不能计为通过，也不据此宣称全部验收完成。

## 实施与复审修复

| 环节 | 最终行为 | 主要位置 |
|---|---|---|
| 私有工作记录 | `record_fact` / `report_finding` 为实际 Worker 返回稳定节点引用及 `staged/published`；未提交观察只对当前意图可读。检查点持久化，资产登记与审批仍即时生效 | `apps/server/src/db/worker-drafts.ts`、`src/tools/graph.ts`、`src/tools/findings.ts`、`src/tools/context-read.ts` |
| 原子最终提交 | `complete_intent` 同一事务发布节点、边、锚点、漏洞及证据绑定、验收清单、意图终态、持久结算事件；重复提交不重复发布 | `src/tools/coordination.ts`、`src/db/worker-drafts.ts`、`src/db/sql/schema.sql` |
| 提交即停止 | pi 原生 `turn_end` 边界在工具结果持久化后停止；同批后续工具被拦截；不再请求模型写结束语 | `src/pi/runner.ts`、`src/agent/roles.ts` |
| 中断及收尾 | 提前两轮收尾，时间预留为总时限 10%、最多 30 秒；收尾工具集只允许必要读取、整理和提交。故障保留真实原因、部分观察及恢复位置；未验收观察不能证明目标 | `src/pi/runner.ts`、`src/engine/worker-outcome.ts`、`src/engine/engine.ts`、`src/tools/goals.ts` |
| 黑板协同 | 取消 Agent 对 Worker 的自由文本 steering；Main 保留界面进度事件但不注入 Worker 对话。旧会话中的反馈消息也从模型输入过滤。触发只传任务、节点、版本等引用 | `src/engine/engine.ts`、`src/engine/conversations.ts`、`src/engine/triggers.ts`、`src/pi/runner.ts` |
| 按空位规划 | 全局数据库锁统一计算运行、复测、待领取、规划预留；Planner 按本轮名额提交提案，持久决策及图版本校验通过后激活 | `src/engine/coordinator.ts`、`src/tools/intents.ts`、`src/db/exploration.ts` |
| 最终事件补位 | 会话退出并释放名额后发布去重唤醒；800 ms 合并。检查点、暂存观察不触发自动派单。一个 Worker 结束可以补位，其他 Worker 保持原意图 | `src/db/worker-drafts.ts`、`src/engine/engine.ts` |
| 来源任务 | 来源仍只读；完成事件唤醒一层关联任务，规划提案同时核对来源图版本；旧来源意图不变成本任务可执行队列 | `src/db/worker-drafts.ts`、`src/engine/coordinator.ts` |
| 显式用户派单 | 保留 Main 的宿主授权，仍受范围及全局名额限制；自动旧队列必须经重新评估 | `src/db/exploration.ts`、`src/tools/intents.ts` |
| 界面统计 | 运行人数以有效租约/名额为准；区分待评估、待领取、规划预留和退出中，避免把历史 `running` 节点当成当前并发 | `src/http/routes/tasks.ts`、`src/http/routes/compat.ts`、`web/src/app/(main)/function/tasks/detail/` |

最终复审另外发现并修复了：

- 已提交但未退出时进程被强杀，重启可能漏补结算记录：新增持久结算恢复，不重新执行模型或意图。
- 过期规划提案重新评估时可能保留旧 contract：现在更新依据与验收条件，并保留前版追溯。
- 部分观察恢复后已验收，仍保持 `unverified`：最终提交时在授权内更新验收标记，沿用原节点，不重复写事实。
- `prove_goal` 与最后一次自动领取竞争：领取事务内重新检查目标终态，显式用户派单语义保留。
- SDK 停止后的合成取消消息被误记为额外模型失败：在请求边界检查取消，只记录实际待响应请求；原生 pi 确定性回归确认物理请求数与审计数一致。
- 已原子提交的历史结果在退出阶段因后续授权变化被改成失败：退出记录原始验收结论；当前图谱投影与目标证明仍执行实时授权校验。
- 总览统计串入全局/其他任务数据：任务详情与 `/api/stats?task=...` 使用一致的任务范围及租约统计。

## 八类角色验证矩阵

所有角色保留自定义正文，独立注入宿主约定，能力仍由工具装配及宿主校验限制。候选正文见 [prompt-candidates.json](evidence/blackboard-20261019/prompt-candidates.json)，不会自动替换自定义内容。

| 角色 | 允许行为与结束条件 | 本轮证据 |
|---|---|---|
| Goals | 保存范围、约束、目标；保存完成退出 | 原生装配/提示词专项、迁移回归 |
| Planner | 读取已发布图，按空位提案，保存决策后退出 | 原生确定性多轮、真实 DeepSeek 两轮、过期提案回归 |
| Main | 用户对话、审批、显式控制；无目标执行能力、无 Worker 私聊 | 装配权限、反馈过滤、历史恢复及任务 HTTP 回归 |
| Worker | 当前一条意图、私有工作记录、集中提交、停止 | 原生停止、重复提交、并发、两种强杀、真实首意图 |
| Auto | 创建/查询/控制平台任务；用户调整写持久黑板记录 | 独立会话和工具边界回归 |
| Pentest | 独立授权会话；绑定任务后才可写入，不领取 Worker 意图 | 独立会话及任务绑定回归 |
| Reporter | 读取已发布漏洞及证据版本、保存报告后退出 | 证据版本、必要保存与持久触发回归 |
| Retester | 固定快照范围复测，保存结论，宿主更新漏洞状态 | 定向权限、结果提交、与 Worker 共享全局名额回归 |

除 Planner / Worker 外，其他角色本轮没有新增真实供应商行为测试；不能将确定性回归等同于真实模型全角色验收。
