# 探索图按需读取优化复审

2026-10-19。本轮聚焦 Agent 的只读工具与总览计数，保留已有工作区修改，不改变事实写回、Agent 权限、意图调度及前端图形界面。

## 完成的调整

- `graph_overview` 默认返回目标索引、授权后的计数和读取入口；显式 `view: "recent"` 保留原有近期态势、覆盖和待办摘要。Planner 启动时仍由宿主提供已有的有界态势及增量上下文，没有改成完全盲查。
- 总览的节点／漏洞计数在 PostgreSQL 内按原授权函数聚合，不再把所有事实和漏洞对应的完整节点取回应用内存后计数。修正无资产锚点的旧漏洞漏计。
- `context_search` 默认每页 10 项、最多 50 项，只取短摘要、状态、引用和版本；节点证据和活动完整输出不再作为查询结果传回应用。全文匹配仍在数据库内进行。中文长摘要额外受 12 KiB 页预算约束，仅推进到实际返回的最后一项，避免截断后跳过内容。
- 混合检索活动与节点时，按意图过滤现在也能找到该意图 `yields` 关联的事实／漏洞，与纯节点检索一致。
- `context_get` 新增 `view: "summary"`。`parents`／`members` 改为数据库端授权后分页，每页最多 20 个引用，不再一次读取全部上游／冷图成员的完整 payload。详情和指定字段仍使用已有 `field`、`version`、`offset` 续读。
- 修正总览指向已从实际工具集移除的 `list_facts`／`expand_index` 等提示，统一推荐 `context_search/context_get`。已识别的旧内置工具说明使用新说明，自定义说明保持原值。

## 接口与兼容

工具名称和角色绑定不变，不增加 HTTP API 或数据库迁移。`graph_overview` 增加 `view: "summary" | "recent"`，默认值为 `summary`；需要旧态势字段的调用显式选择 `recent`。

`context_get.items[]` 新增摘要视图及关系 `cursor`。关系读取同时返回 `page_cursor`、`next_cursor`：有 `next_offset` 时，沿用当前 `page_cursor`、版本及 offset 读完本页；之后使用 `next_cursor` 并将 offset 重置为 0。游标绑定任务、角色、节点、节点版本和关系类型；本页内容哈希防止分段读取期间成员内容或授权变化造成错误拼接。新增节点不会混入已有 ID 上界的关系页。

旧单节点 `ref` 调用路径仍保留。旧关系读取若只带非零 offset、不带页游标，明确要求从首屏重新读取，避免把旧全量内容的偏移误用到新分页结果。完整原始证据不删除、不改写；未展开不代表节点不存在。
