# Worker 意图内替代方法与线索反馈

参考 [Series Worker](https://github.com/neouks/series/blob/main/agent/worker.go)，强化当前问题内的方法选择及共享事实反馈，保留本平台单意图边界、证据收敛与人工控制。

- 一次方法失败不自动否定整个问题；根据已观察到的错误和具体缺口选择合理替代方法，不等 Planner 提醒、不原样重试。
- 已有充分证据不换方式重复确认；方法耗尽、缺少必要输入或授权、进入预算收尾时记录原因与恢复条件并退出。
- 禁止把权限拒绝、暂停、取消、主动停止和超时当作应绕过的障碍。
- 有价值的范围外线索写入现有 fact：summary 标记待规划线索，detail 区分观察、推断及未验证部分，evidence 保留原文；最终总结引用记录，Planner 按共享事实读取。
- 不为线索追加访问、不扩展验收项、不自行派单、不将线索作为已确认漏洞。
- 同步默认提示、宿主协议、Worker 启动上下文及 record_fact 字段提示。系统提示中策略只出现一次，其他角色不注入 Worker 策略。
- 精确升级上一版内置 Worker 默认提示词，追加历史；保留自定义内容、迁移幂等与用户主动选择的旧版本。

## 验证结果

类型检查通过。相关单元回归 14 项通过；新策略隔离数据库测试 3 项通过；运行时与历史提示迁移回归 14 项通过，包括工具限制、暂停、取消、归属变化、依据变化、解绑、禁用、任务暂停、跨范围资产，以及会话压缩、重试和恢复。

运行时测试使用独立数据库。旧 Planner 合成模型用例直接调用 add_intent、不执行工具发现，因此测试配置显式设该工具为常驻；未改变生产配置。

真实模型为现有 Worker 配置的 `deepseek-flash`。使用实际系统提示、workerMandate、record_fact 与 Planner 的 context_get；执行工具仅能读取固定合成本地样本，无目标网络访问或任意文件读写能力。

| 场景 | 实际行为 |
| --- | --- |
| 首次方法失败 | structured 解析失败后改用 text，得到随机样本值，汇总写回一次后结束 |
| 读取中遇到范围外线索 | 只读 current 一次；事实摘要、详情和证据记录模块 B 超时配置的未验证线索；Planner context_get 成功读回；未读 related |
| 已有充分共享证据 | 零工具调用、零新增事实，引用已有记录直接结束 |
| 合理方法均失败 | structured、text 各试一次，写回 unknown 与恢复条件，不循环尝试 |
| 用户禁止替代方式 | structured 失败后未使用被禁止的 text，记录授权限制并退出 |

检查了上述场景的 15 次实际模型请求：策略单份、工具 Schema 名称不重复；事实写回无错误，意图约定未改变，也未创建新意图。读取工具中的预设失败属于场景输入。

复现（在 `apps/server`，需要本地 PostgreSQL 及已配置模型）：

```sh
node --import tsx scripts/evaluate-worker-strategy.mts --run --out=/tmp/worker-strategy-new-run
```

生产数据库强制只读，仅取模型配置；每次验证创建并删除独立 `test_` 数据库。未启动生产调度器、未修改现有任务、未部署或重启 8787。

本机原始记录：替代方法最终策略验证位于 `/tmp/fate-worker-strategy-20261120-v3/alternative`，其余四项及 Planner 读回位于 `/tmp/fate-worker-strategy-20261120-v6`；运行时回归位于 `/tmp/fate-worker-strategy-runtime-tests.txt`。

验证过程中修正了夹具缺少 Worker 领取归属、旧断言匹配已变更的线索格式的问题；模型暴露的重复确认和遗漏摘要问题促成提示词及字段说明调整。一次模型网络读取超时后重跑未完成场景。这些是固定合成场景的真实模型验证，不代表所有任务或模型都能保证相同行为。
